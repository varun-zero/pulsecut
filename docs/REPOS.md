## 2. Cherry-pick list — the one feature to borrow from each of the top 8

Ranked by (relevance to PulseCut × license freedom × implementation quality).

1. **stream-sentry — candidate fusion + boundary clamping (`services/ai_worker/engine.py`).** HOW: `ChatFeatures.measure()` keeps a 5-min event deque; bins the last 5 min into 30 × 10-s bins, uses `median(bins)` and MAD (×1.4826) as a *robust* baseline: `robust_z = (unique_users_now - baseline) / max(1, 1.4826*MAD)`, then `score = min(1, robust_z/8) * min(1, unique_ratio*2)`, gated at ≥8 messages and ≥5 unique users. `CandidateEngine.consider()` fuses 5 weighted signals (semantic .30 / chat .25 / audio .20 / visual .15 / platform_event .10), **drops missing modalities and renormalizes the remaining weights**, requires ≥2 signals ≥0.5, threshold .65, dedupes the same event within ±90 s and caps 3 candidates per rolling media-hour. `refine_boundary()` snaps the cut to nearest VAD/sentence boundary ≥5 s before/after the core, else falls back to T−40 s/T+15 s, flags >90 s windows for review. MIT — adapt directly.

2. **stream-highlight-bot — segment rolling buffer + splice extraction (`streambot/capture/buffer.py`).** HOW: ffmpeg's segment muxer writes fixed-length `.ts` files; `RollingBuffer` tracks `(index, path, start, duration)` with a lock, prunes when `seg.end < newest_end - (buffer_seconds + keep_margin)` (margin 90 s keeps in-flight clip windows alive), anchors wall-clock→stream-time via `_wall_t0`. `extract(start,end)` selects overlapping segments, writes a concat-demuxer list, computes `offset = start - segs[0].start`, and runs `ffmpeg -f concat -safe 0 -i list -ss offset -t target -c:v libx264 -preset veryfast -crf 20 -c:a aac`; if coverage is incomplete it clamps to available segments instead of failing. No license → rebuild this design in Rust.

3. **nirvagold Stream Clipper (Rust) — median/percentile audio spike + combo scoring (`audio/analyzer.rs`, `highlight/scorer.rs`).** HOW: decode WAV → rayon-parallel fixed chunks; compute RMS and peak per chunk; `baseline = median(rms)`, threshold = percentile (75/82/90/95 by sensitivity) with fallback `baseline*(1+0.35*sensitivity)`; require local spike > previous and > threshold, filter by WebRTC VAD `voice_ratio > 0.3` (30 ms frames, `VadMode::Aggressive`, 16 kHz resample). Then pair overlapping audio/chat windows: `combined = (audio*wa + chat*wc) * combo_bonus` (default 1.5), clamp to 100; unpaired spikes get weighted single scores. `merger.rs` NMS: sort by start, merge when overlap/min_duration > 0.5, keep higher score, union reasons. MIT — port almost line-for-line to `pulsecut-detect`.

4. **livestream-highlight-clipper — per-second 3-branch scoring + half-peak adaptive padding (`resonance/scorer.py`, `resonance/peaks.py`).** HOW: bucket chat/ASR/audio into 1-s bins; activity = `.5*density_norm + .25*velocity_norm + .25*(.7*energy+.3*energy_velocity)`; emotion = `.55*excitement_ratio + .20*repetition(1-unique_ratio) + .15*sentiment_intensity + .10*polarity`; overlap = CJK character Jaccard between chat and ASR text **minus a stop-char set**; total = `.4*activity + .4*emotion + .2*overlap`. Smooth with `gaussian_filter1d(sigma=5)`, threshold `max(mean+1σ, .15)`, `find_peaks(height, distance=min_gap/step, prominence=.05)`, keep top-N. Padding: scan left/right while `smoothed >= 0.5*peak`, clamp pads to 5–45 s before / 8–60 s after. MIT — reimplement smoothing/peaks with a small Rust FIR + local-max scan.

5. **Clips Kitty — 9:16 face-tracking reframe with hold-then-move (`video/tracker.py`, `video/framing.py`).** HOW: YOLOv8 detections chained into tracks by IoU; TalkNet (not mouth motion) decides who speaks; `pick_focus()` picks the talker only if talk rate > floor and >1.4× runner-up, else the most prominent subject; `HoldMove` is a 2-state hysteretic pan controller (HOLD until drift > 0.055 of frame width, MOVE with smoothing 0.45 + pan-speed clamp 0.30/s until error < 0.012), target is a trailing median so one bad box can't yank the crop; scene cuts snap the crop and reset mouth state. AGPL → implement the *idea* (hysteresis + speaker lock + cut reset) with Rust/OpenCV/ORT yourself.

6. **SparkReel — explainable fusion + narrative payoff windowing (`fusion/scorer.py`, `fusion/segment.py`).** HOW: `fused(t) = Σwᵢsᵢ(t)/Σwᵢ` over active signals only (a modality with `max ≤ 0.02` is excluded from the denominator), moving-average smoothed; peaks are local maxima ≥ min_score, greedily spaced ≥ min_gap, capped; window expands across the contiguous above-threshold region then pads/clamps. `segment.py` classifies every bin as talk/hype/reaction/action/lull from signal combinations and majority-filters label flicker; payoff is placed at 70–80% of the clip by kind with a kind-specific minimum lead-in, opening on the rising edge (0.3 s pre-roll). MIT — good direct spec.

7. **Live Content Intelligence — 7-signal weighted scoring with presets and contributions (`services/signal-engine/src/signal_engine/{scorer.py,model.py}`).** HOW: all signals normalized to 0..1 by Pydantic; `score = 100*Σ(wᵢ·vᵢ)/Σwᵢ`; presets `default` (threshold 72), `fps` (74, audio×1.30/chat×1.25), `small-streamer` (68, viewer×0.75/keyword×1.15); returns per-signal `contributions` for explainability. The README adds the missing piece: normalize each channel against **its own rolling behavior**; reviewed clips become calibration data. MIT-text → reimplement in Rust, keep the preset JSON format.

8. **Auto-Clipper — voice-trigger clipping with lookback (`analysis/clip_trigger_detector.py`).** HOW: transcribe with faster-whisper (fallback openai-whisper) using word timestamps, build one regex from trigger phrases (multi-word phrases get `\s+` between words; bare `clip` gets a negative lookahead `(?!\s*(?:ping|ped|per|board|s|art))` to kill "clipboard/clipped"), then for each match emit a clip covering the preceding 30 s (`clip_duration`, `pre_pad=5`). Hybrid mode runs CV/YOLO/voice in parallel for recall. MIT — port the regex and trigger→window mapping into `pulsecut-detect`.

**Runners-up worth one line each:** `social-media-scheduler/packages/platforms/src/types.ts` = publish adapter interface (MIT, use it); `postiz-app/.../social.abstract.ts` = error taxonomy refresh-token/bad-body/retry/disconnect (AGPL, idea only); `autoclipper-vadlapati/backend/app/services/clipper.py` = yt-dlp `download_sections` to fetch only `[start,end]` (no license, idea only); `streamclipper/clip.py` = `clip_time = (Nightbot-Message-Timestamp_µs - stream_start)/1e6 + delay` (CC BY-NC, idea only).

## 3. Technical details worth stealing (implementation notes)

- **Rolling buffer strategy.** Keep GOP-aligned `.ts`/fMP4 segments on NVMe (stream-sentry: 15-min ring, per-segment SHA-256 + size in manifests: `apps/ingest-worker/src/index.ts:146`, `apps/ingest-worker/src/media.ts:19`). Track stream-relative time separately from wall time (anchor once: `buffer.py:47-48`). Prune with a safety margin so a T−40 s lookback never dangles. Splice via concat demuxer + `-ss offset -t target`, clamp partial coverage rather than fail. Clip window = **T−40 s … T+15 s**, later refined to 20–55 s (stream-sentry README timeline).

- **Chat velocity thresholds.** Strongest version: robust z-score over 10-s bins against a 5-min median+MAD baseline (`engine.py:78-99`), not a raw ratio; require ≥8 messages / ≥5 unique users; drop bots, raids, history and events >5 min late; dedupe identical messages from the same actor. Simpler alternative: `threshold = median(messages/window) * rate_multiplier` with per-window unique users, keyword count, emote density and caps ratio (`nirvagold chat/analyzer.rs:39-45, 75-104`). Marketing number "≥300% above 5-min baseline" (stream-sentry README) ≈ `rate_multiplier 3`.

- **Emote burst detection.** Two usable definitions: (a) `emote_ratio = (# current messages with emote_count>0) / (# current messages)` fused with the robust-z velocity and `unique_ratio` (`engine.py:95-96`); (b) `emote_density = emote messages / total messages` per window, paired with `caps_ratio = uppercase letters / alphabetic letters` as an excitement proxy (`nirvagold chat/analyzer.rs:83-92, 124-145`). LCI treats `emote_burst` as a standalone 0..1 signal (weight 0.90). Guard against gifted-sub/bot floods by counting **unique chatters**, not messages (`clips-studio/analysis/hype.py:19-23`).

- **Signal fusion.** Always normalize each signal to 0..1 first, exclude dead/missing modalities from the denominator, then weighted-average (`sparkreel/fusion/scorer.py:41-61`; `engine.py:127-132`). Require ≥2 independent signal families to agree before firing (prevents single-sensor false positives), dedupe the same event in a ±90 s window, and cap clips per rolling hour (`engine.py:133-157`). Add per-channel learned biases only after ≥8 positive feedback events, max ±20% shift, renormalized (`clips-studio/creator/learning.py`).

- **Sentence-boundary clamping.** From VAD/whisper word timestamps collect candidate boundaries; choose the closest boundary ≤ core−5 s for start and ≥ core_end+5 s for end; fall back to fixed T−40/T+15; reject >90 s to human review; flag source-edge and <20 s windows (`engine.py:173-192`). Complementary half-peak adaptive padding: scan until score drops below ½ peak, clamp to configured min/max (`resonance/peaks.py:41-69`). ASR word boundaries: `services/ai_worker/audio.py:57` uses Silero VAD `min_silence_duration_ms=300`.

- **ASS caption rendering.** faster-whisper with `word_timestamps=True, vad_filter=True` → group into cues by max words / max line chars / 0.7 s gap → write ASS with `PlayResX/Y`, numpad alignment (2 bottom / 5 center / 8 top), colors as `&HAABBGGRR`, and **one Dialogue per word** for karaoke (current word `{\c accent\fscx112\fscy112}` then reset) (`streambot/subtitles.py:30-130`). Burn with `ffmpeg -vf ass=file -c:v libx264 -crf 20 -c:a copy`; write the ASS in the clip's own directory to avoid Windows drive-letter escaping in the filtergraph (`subtitles.py:144-158`). Extra robustness from Clips Kitty: split cues on speaker turns, script-specific fonts to avoid tofu, and even-spaced fallback timings when word timestamps are missing (`video/captions.py`).

- **9:16 face-tracking reframe.** Sample faces at 5 fps with MediaPipe, confidence ≥0.6; pick max confidence×area initially, then nearest-to-previous-center (L1) to keep identity; smooth x/y with **One-Euro filters** (`alpha(cutoff,dt)=1/(1+1/(2π·cutoff·dt))`, adaptive cutoff `min_cutoff + beta·|velocity|`); reset filters on scene change and hold last crop when no face is found (`poc/phase05/tracker.py:11-83`). For a talk-heavy stream, make "who is speaking" (TalkNet/ASR diarization) override pure prominence, add a pan-speed clamp and hysteresis, and snap on hard cuts.

- **Non-destructive EDL.** Treat the edit as immutable data: a canonical EDL JSON schema (`packages/contracts/canonical-edl.schema.json`), hash it (`computeEdlHash`), and make every edit a new revision with strong ETag checks; any edit invalidates the previously rendered artifact (`apps/api/src/editor/routes.ts:321-356`). The render worker verifies EDL hash, frozen asset checksums and font identity *before* decoding, and reports QC on output (`apps/render-worker/src/process.ts:132-147, 225-232`). This is the model for `pulsecut-app`'s editor: never overwrite media, only append revisions.

- **Multi-platform publish abstraction.** Define one adapter trait: OAuth URL/exchange/refresh, `getCapabilities()` (direct-public?, app review?, chunked upload?), `validatePost`, `publish`, `getPublishStatus`, `fetchAnalytics`, with an `idempotencyKey` on every publish (`social-media-scheduler/packages/platforms/src/types.ts:9-110`). Never retry a failed publish blindly: mark ambiguous outcomes `needs_review` and require explicit manual retry (that repo's README). Postiz adds a useful error taxonomy — `refresh-token`, `bad-body`, `retry`, `disconnect` — and a `checkPostStatus()` hook for providers that return pending (`social.abstract.ts:174-239`). Stream-sentry goes further: verify artifact SHA-256 == approval snapshot before upload, and use resumable uploads to reconcile unknown outcomes (`apps/api/src/publishing/publisher.ts:48`).

- **Per-creator learning.** Ideal guardrailed version: log positive actions with weights (`exported=2.0`, `captions_edited=1.0`, `timestamps_adjusted=1.0`), wait for ≥8 signals, compare weighted mean subscores of kept clips against the creator's own all-clips baseline, clamp each weight multiplier to ±20%, renormalize (`clips-studio/creator/learning.py:20-99`). Lighter alternative: running mean of user trim deltas (`start_delta = new_start - ai_start`), clamp input ±20 s, ignore deltas <0.3 s, require ≥3 samples, apply max ±8 s (`livestream-highlight-clipper/ml/boundary_adaptation.py:64-108`). Ranking: ridge-linear model over 10 features, standardized, `(XᵀX + 0.2·I)w = Xᵀy`, ≥8 samples, ship weights as JSON with MAE/RMSE/correlation (`ml/feedback_ranker.py:200-260`).

- **Human approval gate.** Bind approval to an immutable snapshot: require explicit `publish_approver` permission + tenant match, `structuredClone` the snapshot, hash it, 24-h TTL; validation rechecks TTL, revoked/rejected/superseded status, tenant and hash before any upload (`stream-sentry/apps/api/src/publishing/approval.ts:25-148`). Any edit to EDL/caption/crop/metadata creates a new snapshot, which invalidates the old approval. For Postline's honest counterpart: public posting stays blocked until provider approvals are real; ambiguous publish → `needs_review`, no fake success.

- **Other small wins.** Voice-trigger lookback: default 30 s before the phrase, `pre_pad=5` (`Auto-clipper/analysis/clip_trigger_detector.py:35-45`). Fast partial VOD fetch: yt-dlp `download_sections: {"highlight": [{"start_time": start, "end_time": end}]}` then re-encode (`autoclipper-vadlapati/backend/app/services/clipper.py:4-19`); for live HLS use 16 concurrent fragments (`Auto-clipper/clip_manager.py:96-99`). Nightbot-style command clip math: `(Message-Timestamp_µs − stream_start)/1e6 + delay`, default `delay=-30` (`streamclipper/clip.py:20-31`). Platform profiles: max duration (TikTok 60 s / Reels 90 s / Shorts 60 s), caption placement that avoids Shorts' bottom UI, per-platform hook tone (`sparkreel/src/sparkreel/styles/platforms.py`).

## 4. LICENSE — what PulseCut can legally copy vs must reimplement

**Safe to copy/adapt into PulseCut (MIT / MIT-text), with attribution** — keep the original copyright + permission notice in a `THIRD_PARTY_NOTICES` file and in distributed binaries/docs:
`stream-sentry`, `stream-clipper-nirvagold`, `livestream-highlight-clipper`, `sparkreel`, `Auto-clipper`, `autoclip-zhouxiaoka`, `social-media-scheduler`.
`live-content-intelligence` ships MIT *text* but GitHub classifies it `NOASSERTION` (its warranty disclaimer is shortened) — treat as MIT-like for ideas; confirm with the author before copying verbatim code.

**Must reimplement from the idea, no source copy:**
- **AGPL-3.0:** `clips-studio` (Clips Kitty) and `postiz-app`. Copying code — or a close structural adaptation — obliges the *whole PulseCut derivative* to be licensed AGPL-3.0 if distributed/network-served. Not acceptable for a proprietary/mixed-license product. Reading their comments and reimplementing the algorithms in original Rust is fine (ideas/algorithms are not copyrightable); keep their LICENSE files intact in research and do not vendor source into PulseCut.
- **CC BY-NC 4.0:** `streamclipper` — no commercial use. Idea only.
- **No license (all rights reserved by default):** `stream-highlight-bot`, `autoclipper-vadlapati` — no LICENSE file anywhere; do not copy code, even though the algorithms are described above.
- `postiz-app` also has `CCLA.md`/`ICLA.md`; not relevant unless contributing upstream.

**Operational rules for this project:**
1. All clones stay under `research/repos/` as read-only evidence with original LICENSE files; they are not compiled or linked into PulseCut.
2. When porting an MIT algorithm, write fresh Rust; note the source repo + file + MIT copyright in `THIRD_PARTY_NOTICES.md` (and explain in code comments where a non-obvious trick came from).
3. For AGPL/NC/no-license repos, document the borrowed *idea* and the independent implementation in `docs/`; never paste their code, prompts, or config verbatim.
4. Model weights, brand assets and caption fonts are separate from code licenses — check each asset's own terms before bundling (e.g. YOLO weights, TalkNet, MediaPipe models, Postiz fonts).
